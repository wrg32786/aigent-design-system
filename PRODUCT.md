# Product

## Register

Open-source, installable, agent-native design and production system for immersive websites, cinematic decks, product interfaces, inspiration forensics, creative media, browser repair, and structured visual judgment.

## Users

- Builders using Claude Code or another capable coding agent who want professional, product-specific design rather than generic generated pages.
- Designers and developers who need reusable website, deck, interface, video, 3D, gallery, motion, and inspiration systems without adopting one framework.
- Solo operators and small teams that need to study references, create an original direction, find or produce assets, build, inspect, and ship without assembling the workflow from scratch.
- The Aigent team, which uses this repository to preserve and extend its design and production knowledge.

## Purpose

Aigent turns design and production judgment into installable agent knowledge and verifiable tooling:

- one primary design-team router plus specialist skills
- deterministic design intelligence
- design forensics and Design DNA
- reference synthesis and originality controls
- layout, type, color, motion, media, and interface doctrine
- complete page, deck, and interface systems
- creative resource catalog and production pipelines
- video, 3D, Spline, Three.js, GSAP, Remotion, and HyperFrames routing
- provenance and performance budgets
- Aigent Taste generated-design checks
- Aigent Resolve browser-measured QA
- Aigent Vision structured rendered critique
- constrained publishing guidance
- fixed eval briefs and deterministic checks

Aigent installs into the user's real repo. The coding agent remains the interface and the project files remain the source of truth.

## Core loop

```text
Shape → Inspire → Synthesize → Produce → Build → Taste → Resolve → See → Polish
```

The system is incomplete if it studies inspiration without transformation, recommends advanced media without a production reason, stops at a first successful render, or claims completion without inspecting the real result.

## Success

A successful adopter can:

1. Install Aigent into a repo in one command.
2. Open Claude Code and speak naturally without learning an Aigent command vocabulary.
3. Let the `aigent-design` router choose the relevant specialist knowledge automatically.
4. Have Claude ask only the high-value creative questions the brief is missing.
5. Invite references when they improve the direction without blocking users who have none.
6. Develop multiple viable visual directions before substantial greenfield commitment.
7. Define product truth and a distinct visual world before decoration.
8. Convert reference evidence into Design DNA and synthesize it rather than copying one source.
9. Generate an inspectable layout, typography, motion, media, and runtime plan.
10. Find or create assets under understood rights and appropriate performance budgets.
11. Build a cinematic page, immersive deck, product interface, or other supported experience in the real codebase.
12. Produce desktop, mobile, reduced-motion, loading, failure, empty, error, and disabled states where relevant.
13. Run Aigent Taste and review repeated generated-design defaults.
14. Run Resolve against the rendered browser and repair root causes.
15. Inspect rendered captures with Vision for composition, hierarchy, originality, emotional resonance, and finish.
16. Ship a result that makes sense without its references and does not inherit Aigent's own brand unless selected deliberately.

## Proof

- Canonical templates prove cinematic pages, guided decks, product UI, progressive 3D, Spline, video scrubbing, and resource galleries.
- Inspiration Intelligence proves evidence capture, synthesis, influence controls, and originality checks.
- Aigent Taste proves deterministic generated-design smell detection.
- Aigent Resolve proves ranked root-cause repair, multi-viewport evidence, run comparison, and bounded mechanical completion.
- Aigent Vision proves rendered visual review rather than code-only confidence.
- CI exercises the one-command install, registry, core intelligence, QA systems, browser smoke, and visual capture.

Templates prove craft. They are not universal skins or clone targets.

## Personality

Decisive, cinematic, practical, open.

Documentation should sound like a design director who can maintain the code and production pipeline: specific, plainspoken, and willing to remove an effect, component, dependency, or reference that does not earn its cost.

## Anti-references

Do not drift into:

- a separate IDE or application shell competing with the user's coding agent
- a clone command disguised as inspiration
- one reference controlling layout, type, palette, motion, interaction, and media
- exact source copy, assets, marks, section order, type pairing, or keyframes
- a cyan Aigent clone for unrelated products
- generic dark AI marketing with neon gradients and floating orbs
- identical feature-card grids as the whole page structure
- component-library visual soup
- a huge menu of overlapping skills exposed to normal users
- a “free” recommendation that ignores commercial rights
- generated video or 3D treated as a finished web asset
- live Three.js where a poster, video, or simpler browser feature would work
- decorative motion on every section
- integrations installed without need
- benchmark scores that fabricate visual judgment
- documentation-only recipes presented as complete implementations

## Constraints

- Static HTML, CSS, and JavaScript remain first-class.
- Playwright is a development and QA dependency, not a reason to impose a framework on user projects.
- Integrations and external components are opt-in and isolated.
- Existing Aigent-branded templates remain compatible.
- Accessibility, reduced motion, focus, loading, failure, empty, error, disabled, and mobile states are part of the design.
- Production assets require provenance and resolved rights.
- Inspiration captures, source masters, credentials, and private records stay out of public output.
- Third-party material is not vendored without license review and required attribution.
- Inspiration similarity is a review heuristic, not legal advice.
- Mechanical Resolve passage never substitutes for visual judgment.
- A screenshot existing on disk is not proof that the agent inspected or understood it.
- Human or operating-agent design judgment remains explicit rather than hidden behind an automated taste score.

## Publishing

Publishing is an agent-run production step, not a separate product surface. When the user asks to ship, Aigent should checkpoint the intended source, export only referenced public dependencies, use the chosen provider's official tooling, verify the public artifact or URL, and keep credentials in the provider's official authentication flow.
