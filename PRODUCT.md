# Product

## Register

Open-source, installable, agent-native design and production system for immersive websites, cinematic decks, product interfaces, and the media behind them.

## Users

- Builders using Claude Code, Codex, Cursor, or another coding agent who want professional, product-specific design rather than a generic generated page.
- Designers and developers who need reusable website, deck, interface, video, 3D, gallery, and motion systems without adopting one framework.
- Solo operators and small teams that need to find, generate, clear, optimize, and ship visual assets without assembling the workflow from scratch.
- The AIgent team, which uses this repository to preserve and extend the decisions behind `theaigent.xyz` and `tools.theaigent.xyz`.

## Purpose

The system turns design and production judgment into installable, inspectable assets:

- product and design context
- deterministic design intelligence
- semantic tokens and native motion
- complete page, deck, and interface systems
- reusable interaction patterns
- curated accessible component sources
- creative resource catalog
- asset briefs and production pipelines
- optional runtime integrations
- one consolidated agent skill plus specialist skills
- provenance manifests and performance budgets
- fixed eval briefs, deterministic checks, and browser proof

A user should be able to preserve the engineering contract while replacing the brand, media, composition, and tone.

## Core loop

```text
Shape → Direct → Produce → Build → Verify
```

The system is incomplete if it recommends a visual direction without a layout, recommends cinematic media without a production route, or claims completion without an installable result and browser evidence.

## Success

A successful adopter can:

1. Install a complete system in one command.
2. Define product truth and a distinct visual world before styling.
3. Generate an inspectable layout, typography, motion, media, and runtime plan.
4. Use mature accessible primitives without inheriting several unrelated visual languages.
5. Select the lightest medium and runtime that carries the concept.
6. Find or generate an asset under understood rights.
7. Produce desktop, mobile, poster, reduced-motion, loading, and failure states.
8. Build a cinematic page, immersive sales deck, or trustworthy product interface.
9. Record provenance without exposing private information.
10. Compare output against fixed eval briefs and rendered browser proof.
11. Ship a result that does not look like The AIgent unless that identity was selected deliberately.

## Proof

- `https://theaigent.xyz` is the primary Persuade + Experience showcase.
- `https://tools.theaigent.xyz` is the primary Operate + Read showcase.
- The repository's canonical templates prove cinematic pages, guided decks, product UI, progressive 3D, Spline, video scrubbing, and resource galleries.

The live sites and templates prove craft. They are not universal skins.

## Personality

Decisive, cinematic, practical, open.

Documentation should sound like a design director who can maintain the code and production pipeline: specific, plainspoken, and willing to remove an effect, component, or dependency that does not earn its cost.

## Anti-references

Do not drift into:

- a cyan clone of The AIgent for unrelated products
- generic dark AI marketing with neon gradients, floating orbs, and indiscriminate glow
- identical feature-card grids as the whole page structure
- component-library visual soup
- a huge menu of standalone agent skills with overlapping jobs
- an asset directory with hundreds of unqualified links
- a “free” recommendation that ignores commercial rights
- generated video or 3D treated as a finished web asset
- live Three.js where a poster, video, or model-viewer would work
- glass without valuable media behind it
- mono typography as a costume for technical credibility
- decorative motion on every section
- all integrations installed in the root package
- framework or abstraction before real surfaces need it
- benchmark scores that fabricate visual judgment
- documentation-only recipes presented as complete implementations

## Constraints

- Static HTML, CSS, and JavaScript remain first-class.
- The neutral core remains dependency-free.
- Integrations and external components are opt-in and isolated.
- The public registry installs only declared files.
- Existing AIgent-branded templates remain compatible.
- Accessibility, reduced motion, focus, loading, failure, empty, error, disabled, and mobile states are part of the design.
- Production assets require provenance and resolved rights.
- Source masters and private records stay out of the public repository.
- Third-party material is not vendored without license review and required attribution.
- Human design judgment remains explicit in evals rather than being hidden behind a fake automated taste score.
