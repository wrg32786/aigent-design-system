# Contributing

Contributions should make the system more useful without lowering its design, originality, accessibility, performance, privacy, or licensing standards.

## Good contributions

- a pattern proven in at least two real surfaces
- a complete reference page with desktop, mobile, and reduced-motion behavior
- a corrected resource, license, or pricing record with an official source
- an accessibility, performance, registry, provenance, or inspiration-forensics improvement
- a fixed eval brief or reproducible benchmark result
- a specialist skill that owns a distinct production job not already covered
- an originality safeguard that produces reproducible evidence

## Required evidence

A new visual system or pattern must include:

1. the product or interaction job
2. `use when` and `avoid when`
3. complete HTML or implementation code, not only a prompt
4. keyboard and reduced-motion behavior
5. mobile composition
6. dependency and license notes
7. a registry item when it is intended for reuse
8. repository checks
9. desktop and mobile captures

An Inspiration Intelligence change must also include:

1. source kind and confidence boundaries
2. private-data and access-control behavior
3. Design DNA or schema changes
4. reference-matrix and influence-limit behavior when synthesis changes
5. fixture or deterministic examples that can be redistributed
6. originality and copy-overlap behavior
7. no third-party screenshots, extracted private records, or source assets committed to the repository

## Development

```bash
npm install
npm run check
npm run inspiration
npm run smoke
npm run inspiration:smoke
npm run capture
```

For a registry change:

```bash
npm run registry
pnpm dlx shadcn@latest registry validate wrg32786/aigent-design-system#your-branch
```

## Design discipline

- preserve an established visual world unless the task is explicitly a redesign
- treat inspiration as evidence, not a clone specification
- do not let one reference control more than two design dimensions on whole-surface work
- do not reuse source copy, assets, marks, exact section order, type pairing, keyframes, or code
- do not use identical cards as the default page scaffold
- do not add dependencies for effects the platform or current stack can express
- do not make a marketing composition the default for product UI
- do not vendor external code, media, prompts, skills, or captures without clear redistribution rights
- do not submit generated placeholder claims as product truth

## Commit and pull-request titles

Use plain descriptions of the shipped change:

```text
Add design forensics adapter
Improve mobile scene loading
Correct asset license record
```

Do not include local paths, agent names, internal ticket language, generated session labels, or private operational details.
